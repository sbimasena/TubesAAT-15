4. Resiliensi dan burst

    

      
Burst konkurensi — B-15
Gunakan token Operasi Internal yang masih aktif. Request dijalankan paralel oleh server konsol agar batas koneksi browser tidak membatasi burst.
429 tidak selalu muncul pada burst singkat. Tes Go memverifikasi batas 64 secara deterministik. Ini belum memenuhi P2 60 detik.

      
Outage / recovery — B-10, B-13, B-14
Konsol tidak menghentikan service atau mengubah sumber. Operator menjalankan skenario lewat checker Stage 5; respons hanya dinilai terhadap keadaan yang dipilih.

    

    
Langkah operator untuk bukti yang belum bisa diperoleh dari browser
      
B-01: tinjau docs/member-b-contracts.md. Port Auth 8084 dan timeout 5000 ms masih sementara; batas awal konkurensi 64 ditinjau pada P2.

      
B-04: gunakan scripts/check-member-b.py --start --check-lifecycle dengan env/project lokal. Opsi tersebut menjalankan stack dan restart kedua service B; kendala broker Windows tetap perlu ditangani bersama C.

      
B-13–B-16: checker berikut mengubah outage PVMBG dan stop/start PostgreSQL/Auth, kemudian memulihkannya. Jalankan terpisah dari demo lain:

      
python scripts/check-member-b-resilience.py --env-file .env.member-b.local --project-name NAMA_PROJECT --exercise-outages --burst-connections 128 --output HASIL_DI_LUAR_REPO.json

      
Salin correlation ID hasil konsol untuk mencocokkannya dengan log Auth, API Klien, dan Aggregator. Latensi pada konsol adalah waktu request HTTP melalui relay; latensi outbound dan redaksi log proses perlu bukti dari checker/log.

      
Boundary: konsol hanya memanggil Auth/API Klien. Tidak ada endpoint introspeksi internal, secret layanan, atau akses PostgreSQL pada halaman.
